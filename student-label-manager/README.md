# 生徒情報データベース＋ラベル印刷システム (student-label-manager)

生徒情報を安全に長期保存・検索・編集し、宛名ラベル（F21A4-2）を印刷するための業務用 Web アプリです。
PC での利用を前提としています。

## 概要

- 「生徒を検索 → 生徒情報を開く → ラベル印刷」を最短操作で行うための業務用データベース
- 管理者1名のみのメール＋パスワード認証。未ログイン状態では生徒情報に一切アクセスできません
- 氏名・住所・電話番号・メールアドレス・学校名・保護者名などの個人情報を扱うため、認証・アクセス制御・データ保護を最優先で設計しています

## 主な機能

- メール＋パスワードログイン（管理者1名）、ログイン失敗の回数制限、30分無操作での自動ログアウト
- パスワード変更／パスワード再設定（メールリンク）
- 生徒の新規登録・編集・検索（氏名／フリガナ／学校名／メールアドレスの部分一致）
- 現役／アーカイブの状態管理、アーカイブも含めた検索の切り替え
- 削除（ゴミ箱への移動）・復元・完全削除
- 氏名＋学校名の重複チェック（警告のみ、登録自体は止めない）
- 郵便番号からの住所補完、郵便番号・電話番号の自動整形
- ダッシュボードでの「最近開いた生徒」表示
- 検索結果とは独立した「印刷対象リスト」。何度検索をやり直しても選択済みの生徒は保持され、複数回の検索をまたいでラベル印刷対象を積み上げられる（最大21名）
- ラベル印刷（F21A4-2 / A4 / 21面 / 3列×7行 / 70mm×42.3mm）
  - 1〜21名を自由な位置に配置
  - ラベル内は「住所 → 氏名＋様 → 保護者様」の順に表示（氏名と保護者様は同じ書体・同じサイズ）
  - 保護者様表示 ON/OFF（デフォルト ON、実名は印刷されない）
  - mm単位の印刷プレビュー、印刷位置の微調整（オフセット保存）、テスト印刷モード
  - Windows標準の印刷ダイアログを使用（印刷ボタン→ブラウザの印刷機能）

## 使用方法

### 生徒を登録する

ログイン → 新規生徒登録 → 情報入力（重複警告が出た場合は内容を確認） → 登録する → 生徒詳細ページへ遷移

### ラベルを印刷する

ログイン → 生徒検索（氏名・フリガナ・学校名・メールアドレス） → 検索結果のチェックボックスで印刷対象に追加
→ 検索語を変えて再検索し、さらに追加（最大21名、追加済みの生徒は検索をやり直しても消えません）
→ 画面下の「現在の印刷対象」で内容を確認（不要な生徒は「削除」で除外可能）→「ラベル印刷へ」
→ 各位置に生徒を割り当て → 保護者様表示を確認 → （初回は）テスト印刷モードで試し刷り
→ 印刷位置調整で補正 → テスト印刷モードを解除 → 印刷 → Windowsの印刷ダイアログでプリンターを選択

生徒詳細ページの「ラベル印刷」ボタンからも、その生徒1名を選択した状態で同じ画面に進めます。

## 技術構成（採用理由）

| 項目 | 採用技術 | 理由 |
|---|---|---|
| フレームワーク | Next.js 16 (App Router, TypeScript) | フロントエンドとサーバーを1プロジェクトで実装でき、Server Actions により CSRF 対策が標準で組み込まれる |
| データベース | Supabase (PostgreSQL) | マネージド型でバックアップ機能を持ち、将来の Excel 連携や項目追加にも対応しやすい |
| 認証 | Supabase Auth（メール＋パスワード） | 実績のある認証基盤。パスワードのハッシュ化・再設定メール・セキュアな Cookie セッション管理が標準装備 |
| アクセス制御 | PostgreSQL の Row Level Security (RLS) | DB レベルで未認証アクセスを拒否するため、API を直接呼び出しても生徒情報を取得できない |
| ホスティング | Vercel | Next.js 公式のホスティング先。HTTPS が標準で有効 |

既存アプリ（GitHub Pages で公開する静的サイト）とは異なり、本アプリは認証・DB・秘密情報を扱うため GitHub Pages では公開できません。Vercel にデプロイします。

## セットアップ手順（本番環境）

### 1. Supabase プロジェクトの作成

1. https://supabase.com でプロジェクトを新規作成
2. SQL Editor で `supabase/migrations/0001_init.sql` → `0002_add_furigana.sql` の順に内容を実行し、テーブル・インデックス・RLS を作成（既にアプリを運用中の場合は `0002` のみ追加実行すれば既存データを保持したままフリガナ列が追加されます）
3. Authentication > Providers で Email を有効化（Confirm email は任意）
4. Authentication > Users から「Add user」で管理者のメールアドレス・初期パスワードを**直接作成**（コード上にはメールアドレス・パスワードを一切記載していません）
5. Settings > API から以下を取得
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - anon public キー → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - service_role キー → `SUPABASE_SERVICE_ROLE_KEY`（**絶対に公開しないこと**。ログイン試行回数の記録にのみサーバー側で使用）
6. Authentication > URL Configuration の Redirect URLs に、本番URLの `/reset-password` を追加（例: `https://your-app.vercel.app/reset-password`）

### 2. Vercel へのデプロイ

1. Vercel で GitHub リポジトリ `claudia406/Apps` を import
2. プロジェクトの **Root Directory** を `student-label-manager` に設定
3. Environment Variables に上記3つの値を設定（Production / Preview 両方）
4. Deploy

### 3. バックアップについて

Supabase の無料プランはバックアップの保持期間が短いため、長期保存を前提とするなら
**Supabase Pro プラン（Point-in-Time Recovery 対応）へのアップグレードを推奨**します。
Pro プランでは障害時・誤操作時に任意の時点までデータを復元できます。

## ラベル印刷時の注意（ブラウザ／Windows設定）

- 用紙: **F21A4-2**（A4 / 21面 / 3列×7行 / 1片 70mm×42.3mm）
- F21A4-2 の正確なマージン値はメーカー非公開のため、本アプリは「印刷位置調整（オフセット）」機能を搭載しています。初回は**テスト印刷モード**で実際のラベル用紙に試し刷りし、ずれがあれば調整してください（調整値はブラウザに保存されます）
- 印刷ダイアログでは **「用紙サイズ: A4」「拡大/縮小: なし（実際のサイズ・100%）」「余白: なし」** を選択してください。ブラウザ側で自動縮小（例: 「用紙に合わせる」）が有効だとmm単位の位置がずれます
- 推奨ブラウザ: Chrome / Edge（印刷プレビューの精度が高いため）

## セキュリティ対策

- 未ログイン状態ではページ・API のいずれからも生徒情報を取得不可（Next.js の認証チェック＋PostgreSQL RLS の二重防御）
- パスワードは Supabase Auth 側でハッシュ化して保存（アプリ側で平文を扱わない）
- セッションはセキュアな httpOnly Cookie で管理（本番HTTPS環境ではSecure属性が付与される）
- ログイン失敗が15分間に5回を超えると一時的にロックアウト
- 30分間操作がない場合は自動ログアウト
- Server Actions による CSRF 対策（Next.js標準のOriginチェック）
- React によるエスケープでXSS対策、Supabaseクライアント経由のパラメータ化クエリでSQLインジェクション対策
- 入力値は zod によりサーバー側でも検証
