# どこかへ行きたい (flight-finder)

出発日・帰国日を指定するだけで、目的地を決めずに日本全国の空港発で世界中の往復航空券を比較検索できるWebアプリです。

## 現在の状態(重要)

このアプリは**実際に動作する実装**ですが、接続している航空券データソースは1つだけです。「複数のデータソースを比較できる」という最終目標に対して、現時点でどこまで実現できているかを正直に記載します。

| データソース | 状態 | 備考 |
|---|---|---|
| **Aviasales Data API**(Travelpayouts) | 実装済み・**ただし本番トークンでの動作確認は未実施** | 無料・個人でも即時登録可能。トークンを設定すれば動作する設計だが、実トークンでAPIを呼び出した検証はできていない(下記「未検証事項」を参照) |
| **Duffel Flights API** | 未接続(意図的) | 接続すると航空券の「販売者」になり、日本では旅行業登録が必要になる可能性があるため、法務確認が取れるまで未接続としている |
| **Skyscanner Flights Live Prices API** | 未接続(意図的) | パートナー申請制(審査約2週間、個人開発では承認されない可能性が高い)。申請・承認後に接続可能 |
| **Amadeus Self-Service API** | 利用不可 | 2026年7月17日付でセルフサービス提供が完全終了。現在はエンタープライズ契約のみ |

## 主な機能

- 出発日・帰国日 + 前後の柔軟性(初期値±3日、0〜14日で変更可)を指定した検索
- 日本全国の空港マスターデータ(主要78空港、地域別)から出発空港を選択
- 第1段階: 目的地を決めずに、出発地から見た行き先ごとの参考価格(キャッシュ)を一覧表示
- 第2段階: 選んだ目的地について、日程の柔軟性を適用した複数の日程候補を検索し、実際の価格・航空会社・乗継回数・所要時間(取得できた範囲)を比較
- 「最安値順」「所要時間順」「乗継回数順」「当初日程に近い順」の並べ替え(根拠のない「おすすめ」スコアは作っていません)
- 当初希望日程と実際の候補日程の差分、現地滞在日数を明示
- 参考価格・検索価格・再確認済みなど、価格の信頼性の状態を常にバッジで表示
- データソースごとの接続状況(利用可能/認証情報未設定/申請待ち/エラー)を常時表示
- 外部予約先リンクの安全性チェック(https・許可済みホストのみ)。リンクが無い場合は架空のURLを作らず、その旨を表示
- APIから取得できない項目(荷物条件・運賃変更条件など)は「未確認」と明示し、推測で埋めない

## 未検証事項(本番利用前に必ず確認してください)

Travelpayouts/Aviasales Data APIは無料トークンの発行自体が個人でも可能ですが、**実際のトークンを使ったAPI呼び出しの動作確認はこのセッションでは行っていません**(トークンを持っていないため)。公式ドキュメントの記載に基づいて実装していますが、以下は実際のトークンで検証が必要です。

1. `/v1/prices/cheap` と `/aviasales/v3/prices_for_dates` のレスポンスの実際のフィールド構成(本実装は複数のドキュメント記載を突き合わせて防御的にパースしていますが、実データでズレがあれば調整が必要です)
2. 実際のレート制限(本実装は安全側に同時実行数3・リトライ2回に制限していますが、正式な上限値の確認が必要です)
3. `currency=jpy` 指定が実際に日本円で返ってくるか
4. APIが返す`link`フィールドの実際の形式(相対パスという前提で実装しています)

**本番トークンを設定した後、必ず実際に検索を行い、価格・リンクが正しく表示されることを確認してください。**

## セットアップ

```bash
npm install
cp .env.local.example .env.local
# .env.local に Travelpayouts (https://www.travelpayouts.com/) で取得した
# TRAVELPAYOUTS_TOKEN を設定する(TRAVELPAYOUTS_MARKER は任意)
npm run dev
```

トークンを設定しない場合でも画面は動作しますが、データソースは「認証情報未設定」と表示され、検索結果は0件になります(架空のデータは表示しません)。

## テスト

```bash
npm test     # vitest によるユニットテスト(日程の柔軟性計算、重複排除、予約リンク生成、安全性検証など)
npm run lint # ESLint
npm run build
```

テストは実APIを呼び出さない、純粋なロジック(日程計算・リンク生成・重複排除・アダプターの状態管理)のみを対象としています。実APIとの結合テストは本番トークンでの検証が必要です(上記「未検証事項」を参照)。

## 技術構成(採用理由)

| 項目 | 採用技術 | 理由 |
|---|---|---|
| フレームワーク | Next.js 16 (App Router, TypeScript) | APIトークンをサーバー側(Route Handlers)に隠し、フロントエンドに露出させないため |
| 入力検証 | Zod | リクエスト境界での型安全な検証(既存の student-label-manager と同じ採用方針) |
| テスト | Vitest | 軽量で設定が少なく、純粋なロジックのユニットテストに適している |
| ホスティング | Vercel | Next.js公式のホスティング先。既存アプリ(student-label-manager)と同じ構成 |

既存アプリの多く(GitHub Pagesで公開する静的サイト)とは異なり、本アプリはAPIトークンをサーバー側で保持する必要があるため、GitHub Pagesでは公開できません。

## 本番利用までに必要な作業

1. Travelpayoutsで無料アカウントを作成し、`TRAVELPAYOUTS_TOKEN`(・任意で`TRAVELPAYOUTS_MARKER`)を取得・設定する
2. 実トークンで実際に検索を行い、上記「未検証事項」を確認する
3. Vercelにプロジェクトを接続し、環境変数を設定してデプロイする
4. (任意・将来対応)Skyscanner Travel APIへのパートナー申請、またはDuffel接続時の旅行業登録要否について法務確認を行う

## 今後の改善候補

- 複数の出発空港を1回の検索で同時に扱う(現在は1空港ずつ。API呼び出し数を抑えるための仕様)
- 座席クラス・旅行者数・荷物条件に対応したデータソースが見つかった場合の対応
- 広域探索結果のキャッシュ(同一条件での再検索時にAPI呼び出しを減らす)
- Duffel/Skyscanner接続時のアダプター実装の追加(インターフェースは実装済みのため、承認後は比較的小さな変更で追加可能)
